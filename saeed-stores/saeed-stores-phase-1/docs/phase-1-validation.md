# سجل التحقق — المرحلة الأولى

التاريخ: 04/11/2026

## ما نُفّذ بالفعل

1. طُبِّق سكربت المخطط مرتين على PostgreSQL محلي داخل PGlite مع بدائل محدودة لواجهات Supabase. أُدخلت سياسة قديمة غير آمنة بين التطبيقين للتأكد من إزالتها. النتيجة: **30 فحصًا محليًا ناجحًا**، بما في ذلك RLS، منع القراءة والكتابة المباشرة للزائر على الطلبات، المدير الأول، السعر المحسوب على الخادم، وإعادة الطلب دون تكرار.
2. تم التأكد من تطابق SHA-256 لملف `gradle-wrapper.jar` مع القيمة الرسمية، ووُضع SHA-256 لتوزيع Gradle في ملف إعداد Wrapper.
3. نُفّذ `./gradlew help` باستخدام JDK 17 وGradle 9.8.2 وخيار عامل واحد وذاكرة مخفّضة: **BUILD SUCCESSFUL**. هذا فحص إعداد، وليس بناء تطبيق.
4. نُفّذ تقرير `:customer:dependencies --configuration debugRuntimeClasspath` للهيكل الحالي بنجاح، ولم تظهر فيه تبعية وحدة الإدارة أو حزم Supabase. هذه النتيجة تخص الهيكل الحالي فقط.
5. حلّل محلّل XML ملفات Manifest والنصوص، وحُلّل ملف Version Catalog بوصفه TOML دون أخطاء.

## ما لم يُنفّذ

- لم يُشغّل المخطط على مشروع Supabase فعلي؛ بدائل PGlite لا تمثل كافة سلوك Auth أو Storage أو Realtime.
- لم تُنفَّذ اختبارات أمان واجهة الشبكة على مشروع Supabase التجريبي، ولم يُتحقق من إعداد تسجيل المستخدمين في لوحة Supabase.
- لم تُشغَّل اختبارات Android `test` أو `lint`، ولم يُبنَ أو يُوقّع APK. بيئة التنفيذ الأصلية لا تتضمن Android SDK، وذاكرتها الإجمالية نحو 2 GB؛ الإصدار يحتاج بيئة أكبر أو GitHub Actions.
- لم يُختبر التطبيق على محاكي أو جهاز، ولم تُنفَّذ اختبارات الأداء أو الإتاحة أو تسليم الطلبات.

## تشخيص محاولة إعداد أولى

اختفى Gradle daemon في المحاولة الأولى بينما كانت ملفات JDK وGradle تحت `/tmp` الممتلئ تقريبًا، وهو نظام ملفات مدعوم بالذاكرة. بعد نقل الأدوات المؤقتة إلى ذاكرة القرص وتحرير `/tmp`، نجح **فحص الإعداد فقط**. لا يثبت ذلك نجاح بناء التطبيق الكامل.
